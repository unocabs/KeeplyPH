# Dashboard design proposal: Free and active Premium

30 October 2026. Planning and visual concepts only. Implementation is not approved by this document.

## Problem and evidence

The owner reports that the active Premium checkup looks like an advertisement, asks for a more premium design across the dashboard, and requests a plan comparing Free and Premium before implementation. Returning households should be able to identify available tools and act on upcoming obligations without interpreting promotional copy or many equally weighted panels.

This is direct owner feedback and assistant interface assessment. It does not establish a widespread household problem or a measured comprehension improvement. The research baseline's sections 2.2, 2.3, 2.5 and "What premium should mean" support reliable access, clear next actions and respectful attention. Current source confirms that the dashboard preview shares a promotional structure across access states, and that the existing planner and checkup already supply paid planning capabilities.

## Shared visual foundation

Both plans receive a polished, accessible interface. Use warm ivory workspace surfaces, white content panels, deep ink text, restrained plum actions, thin neutral borders and small consistent outline icons. Use a consistent spacing scale and a restrained heading treatment, with readable sans-serif labels, dates and amounts. Remove repeated lavender containers and excessive nested borders. Keep the recognisable Keeply logo.

Keep the same navigation, core section order and item identity system across plans. Prioritise upcoming dates, any unresolved obligations, useful planning and saved records. Keep the calendar as the default; a compact list in a comparison image is illustrative, not a decision to change that default. Keep item artwork beside names, including every insight contributor, with existing fallback icons for unbranded items or failed images.

## Free and Premium presentation

| Surface | Free | Active Premium |
| --- | --- | --- |
| Sidebar | Warm white with plum selected navigation and a small Free account label | Deep plum with accessible light labels, the same navigation and a clearly visible Premium active account label |
| Upcoming obligations | Existing calendar, next dates, alerts, amounts and actions | Same core experience and access |
| Upcoming spending | Existing next-30-day total, estimates and missing-amount context | Same total, without repeating it in the checkup summary |
| Planning | Existing 30-day planner | Integrated spending checkup result and a direct route to existing longer planning and month comparisons |
| Checkup | No empty locked card or blurred personal data | White functional card with a restrained plum accent, one useful existing insight and View checkup action |
| Records and useful details | Existing records, history, proof and useful-detail suggestions | Same core experience and identity artwork |
| Upgrade messaging | One quiet Explore Premium link in the account area | No upgrade advertisement; show current access and direct tool actions |

The darker Premium sidebar is a proposed visual distinction, not a new theme feature or a reason to lower Free's design quality. Charts must communicate actual existing calculations. Avoid decorative charts, invented savings, budgets, account balances, provider settlement or affordability claims.

## Layout and interaction plan

1. Shared compact page header and primary Add item action.
2. Upcoming calendar with its existing list switch, recognisable item artwork and clear dates. Preserve the existing weekly summary without duplicating it in multiple cards.
3. Any overdue or unresolved work remains discoverable ahead of optional analysis. Use a small calm summary when nothing needs a check.
4. Plan & organise groups the existing spending total and useful details. For Premium, integrate the checkup and a compact route to longer planning here. Use existing planner/checkup calculations; do not derive a supposedly complete household insight from the dashboard's partial item list.
5. Saved records use more considered spacing and fewer redundant descriptions while retaining names, logos, category filtering, sort and all existing destinations.

On narrow screens, preserve this reading order in a single column. Keep the navigation drawer, readable type and touch targets. A darker Premium mobile header can carry the same identity, subject to contrast and device validation. Do not compress item artwork away.

## Access and data states

Paid access and installation gift access use the same functional dashboard, with truthful distinct status labels. Pending checkout stays pending until authoritative activation. Expired access returns to the polished Free presentation while keeping records and everyday capabilities available.

An active Premium account with too little data should see a useful explanation and existing add-amount or add-expense destination. Loading and query failure must not appear as zero expenses or lost Premium access. The more detailed embedded checkup remains contingent on a complete reliable server data path, not just its appearance in the mockup.

Normal entered amounts have no confirmation status. Only estimates and missing amounts receive labels. Payment/completion status remains separate.

## Validation before implementation is considered complete

- Compare whether people identify the current plan, find the next obligation and open an available Premium tool without mistaking it for an upgrade.
- Verify Free, paid, gift, pending and expired states against authoritative access data.
- Check matching dashboard, planner and checkup periods and totals, missing/zero/estimated amounts, insufficient data and query errors.
- Exercise calendar/list, item opening, amount changes, cancellation, failed-save recovery, category filters and sorting.
- Inspect desktop, 390px and 320px layouts, keyboard access, enlarged text, contrast and image fallbacks in Chromium and WebKit. Physical-device behavior remains a separate verification requirement.
- Confirm public pages, metadata and indexing rules remain unaffected by the private dashboard redesign.

## Current result

The comparison image is an illustrative visual proposal using fictional household examples. It is not a screenshot of a running implementation. At the proposal stage, no application source, entitlement rules or hosted account data had changed. Readability, access-state recognition and reduced household effort remain unvalidated hypotheses.

## Subsequent approved preparation

The owner subsequently requested a sample-only Free/Premium switch before the visual redesign. This separate change compares existing plan capabilities with the same fictional records, persists a sample preference during the browser session and keeps private access rules independent. It does not implement the ivory/plum dashboard redesign above. Implementation and verification results are recorded in the research index.
